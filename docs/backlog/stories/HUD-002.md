## Context

Epic: `EPIC-08`. This story builds the machine and turning it
(`docs/wiki/design/components.md`):

- **C-01, the machine.** It shows its tag shape, its class pattern, and a trim
  relative to the viewer (`tokens.md` §1.3). It has a dial with compass detents
  and pips, a live lamp, a committed state and a partner lamp. **The helper-only
  lens glow** needs three things: the machine is in the viewer's `LensView`, the
  room is lit, and the viewer's light is on it.
- **C-02, the player light.** A SpotLight follows the camera. "Light on it" is a
  15° cone test (`architecture.md` D14: direction is presentation).
- **C-16, the dial control.** Detent buttons and a separate Turn press. The
  helper's pinged detent is pre-selected (`mechanics.md` §5, Q-G5). The
  diagnostic failure is shown to the turner only (Q-G4): a ✕ and a shake for
  wrong setting, an hourglass for not live yet.
- **C-17, the turn prompt.** Enabled only for the viewer's own key classes, at a
  distance at most `turn_range_studs`.
- **C-21, the facility pulse.** The visual equivalent of the failure and
  blackout tones.
- **Blackout.** A dark room's lighting is off on every client
  (`RoundView.dark`).

**Which required gate would fail if this story's artifact broke:** `unit`. The
look is `D-1`.

## Acceptance criteria

- **AC-1** — Given a machine, a viewer's `SeatView`, `LensView` and aim, when
  `MachineModel.describe` runs, then:
  - the trim is the viewer's hue with a key glyph iff the machine's class is in
    the viewer's `keyClasses`;
  - it is the partner's hue with an eye glyph iff the class equals `lensClass`;
  - otherwise it is neutral;
  - the glow is shown **iff** the machine is in `LensView.readings`, its room is
    not dark, and the aim cone contains it.

  *Control:* a model that shows the glow from `LensView` alone, ignoring the
  cone, must fail.
- **AC-2** — Given `DialControlModel.describe`, when the viewer's helper has an
  active setting ping on this machine, then that detent is pre-selected. A ping
  by anyone else never pre-selects. A machine that is not the viewer's never
  offers `turnEnabled`.
  *Control:* pre-selecting any player's ping must fail.
- **AC-3** — Given a `TurnResult` reply, when the dial model consumes it, then
  `wrong_setting` and `not_live` produce different glyphs and motion. Each
  refusal reason produces its `voice.md` word. Under reduced motion there is no
  shake, but the glyphs still differ (PT-A6).
- **AC-4** — Given `TurnPromptModel.enabled(machine, viewer)`, when it runs, then
  it is true only for the viewer's own classes. The prompt distance token is at
  most `turn_range_studs`, a test over `Theme` against `MechanicsTuning`.
- **AC-5** — Given `FacilityPulseModel.onEvent`, when a failure or a blackout
  event occurs, then it returns a visual for every audio cue it pairs with
  (PT-A5).

## Contract

The models are pure, in `src/client/models/`, with the signatures in
`components.md`: `MachineModel`, `DialControlModel`, `TurnPromptModel` and
`FacilityPulseModel`, plus `LightCone.contains(cameraCFrameLike,
point, halfAngleDegrees)`. The cone angle is a `Theme` token. The views
decorate `MAP-001`'s anchor parts on the client and send turns with
`ClientTransport.send("Turn", { machine, setting })`.

**Oracle partition.**
- AC-1 to AC-5 are **settled** by `components.md`'s state tables and
  `mechanics.md` §5.
- The cone test is **mechanical** geometry.
