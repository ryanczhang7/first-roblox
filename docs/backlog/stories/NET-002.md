## Context

B4 requires every remote handler to validate "whether the action is legal in the
current round phase". This is the check that makes a whole class of exploit
impossible rather than merely unrewarding: actuating during `Lobby`, signalling
during `Post`, submitting anything at all before seats are dealt.

`NET-001` declared `legalPhases` on every remote definition and left it
unenforced. This story enforces it, in `Wrapper.guard`, at position 4 of the fixed
check order. One file changes and no call site does — which is the payoff for
declaring the field early.

The design reason this matters more here than in a typical game: under the chosen
genre, timing *is* the mechanic. `mechanics.md` §3 makes acting out of turn cost
the same as acting wrongly, and §4 makes the signal stream's ephemerality the axis
of difficulty that out-of-band voice cannot repair. A client that can act outside
its phase is not skipping a formality; it has left the game's clock behind.

**Which required gate would fail if this story's artifact broke:** `unit`.

## Acceptance criteria

- **AC-1** — Given a remote declared legal only in `Round`, when it is called by a
  seated player with valid arguments while the phase is `Round`, then the handler
  runs.
- **AC-2** — Given that remote, when it is called while the phase is `Lobby`,
  `Assignment`, `Resolution` or `Post`, then the handler does not run and the
  rejection reason is `"phase"` in every case.
- **AC-3** — Given that remote called out of phase with **malformed** arguments,
  when it is guarded, then the reason is `"shape"`, not `"phase"` — the fixed check
  order from `NET-001` is unchanged.
  *Semantics:* identity, shape and range run before phase. An attacker sending
  garbage out of phase is told about the garbage; the order is what `TEL-003`'s
  metrics are built on.
- **AC-4** — Given a remote declared legal in **more than one** phase, when it is
  called in each of them, then the handler runs in each; and when it is called in
  any other phase, it is rejected.
  *Control:* an implementation comparing only against the **first** entry of
  `legalPhases` passes AC-1 and AC-2 and **must** fail this.
- **AC-5** — Given a remote whose `legalPhases` is empty, when it is declared, then
  declaration fails.
  *Semantics:* an empty list means "legal nowhere", which is never what anyone
  meant and would silently disable a remote. Making it a declaration error catches
  it at load, not in production.
- **AC-6** — Given the guard, when it determines the current phase, then it reads
  it from the injected `GuardContext.phase()` at the moment of the call, not from a
  value captured when the remote was declared.
  *Control:* an implementation that captures the phase at declaration time passes
  every test that never changes phase, and **must** fail a test that guards once
  and calls in two different phases.

- **AC-7** — Given `src/net/Remotes.luau` and `src/server/round/PhaseMachine.luau`,
  when the exported `Phase` union is read from each, then the two name **exactly
  the same phases**.
  *Semantics:* AC-5 makes "legal nowhere" a declaration error because a remote
  legal nowhere is silently dead. A `legalPhases` entry naming a phase the round
  machine never produces is **the same defect by another route**, and neither AC-5
  nor the typecheck gate catches it — see the Contract block "Why typecheck cannot
  do this".
  *Control:* a sixth phase added to **either** module alone must make this fail and
  must **name the phase that differs**. Assert the extracted set is non-empty and
  contains all five known phases: a guard whose extraction pattern matches nothing
  compares empty to empty and passes, which is the needle-that-cannot-fail failure
  in `rules.md`.

### The rule

    if not table.find(definition.legalPhases, context.phase()) then
        return { reason = "phase", detail = ... }

**Amended in RED (Test Developer, 2026-09-21) — "after `range`" is observable,

### Why typecheck cannot do AC-7, measured rather than assumed

The obvious objection to AC-7 is that the type checker already catches a `Phase`
mismatch. It does not, and the reason is structural. Checked against the tree on
2026-09-21:

```

$ grep -rln 'Wrapper' src/              -> src/net/Wrapper.luau, src/net/Schema.luau
```

`Remotes.Phase`, and an analyser with no expression to check reports nothing.
`luau-lsp` exiting 0 here is the absence of a complaint, not evidence.

the composition root `architecture.md` describes — and that is M3. NET-002's own

### AC-7's guard

The two declarations today, byte-identical apart from the module they sit in:

    src/net/Remotes.luau:33              export type Phase = "Lobby" | "Assignment" | "Round" | "Resolution" | "Post"
    src/server/round/PhaseMachine.luau:122   export type Phase = "Lobby" | "Assignment" | "Round" | "Resolution" | "Post"

**Read both files through `tests/helpers/SourceScan.luau`'s classifier list, not
a hand-written path.** `rules.md` is emphatic and `NET-001` proved the pattern:
`sourceFiles()` / `sourceFilesIn(pathspec)` enumerate through `classify.sh`, so a
module renamed or moved is still found and a probe is excluded by classification.
Assert both target paths are *in* the returned set before reading them — a guard
over a path that silently no longer exists is a guard over nothing.

**Extract the phases and compare as sets**, so that reordering the union is not a
failure but a different membership is. `"Lobby" | "Round"` and `"Round" | "Lobby"`
mean the same type.

**Three vacuity assertions, and they are the point of the criterion:**

1. each extracted set is **non-empty** — a pattern that matches nothing compares
   `{}` to `{}` and passes;
2. each contains all five known phases — so the extraction cannot degrade to
   finding one phase and calling it agreement;
3. the failure message **names the differing phase**, not just "they differ".

The scan is textual, over `SourceScan.codeOnly` output so a union quoted in a
doc comment is not a second declaration. State that limit in the test, as
`SourceScan` and `roblox_runtime_guard_test` both do: a union built by string
concatenation or spread across lines in some future refactor is invisible to it,
and it catches the way the type is actually written today.

### `detail` for a phase rejection

`NET-001` pinned that the **schema's** failure string leads with its kind
(`"shape: ..."`, `"range: ..."`) because the wrapper reads the kind back out of
it. A phase rejection has no schema in the path — the wrapper builds the
`Rejection` itself — so **`detail` carries no `"phase: "` prefix**. `reason`
already says which check fired; a prefix here would be a second, redundant
encoding that a later refactor could let drift from `reason`.

What `detail` must contain, because `TEL-003` emits it and an operator reads it
when a spike appears: **the phase that was current, and every phase that was
legal.** Both halves. RED pins the exact wording; the criterion is that both are
recoverable from the string.

**Amended in RED (Test Developer, 2026-09-21) — what "recoverable" pins, and
what it leaves free.** The test does not pin a sentence; it pins substrings.
For a remote legal in `{ "Round", "Post" }` called in `Lobby`, `detail` must
contain `Lobby`, `Round` and `Post` as plain substrings, must **not** contain
`Assignment` or `Resolution`, and must not match `^phase:`. *Reason:* "contains
`Round`" is a needle that a detail listing all five phases would satisfy, so
the negation - no phase that is neither current nor legal - is part of the
pin; without it, neither half is recoverable. The wording between the names is
GREEN's; the stub's `the phase is Lobby; legal in Round, Post` is one form
that satisfies it. The remote's name may appear in the detail; the test's
remote names contain no phase name, deliberately.

## Out of scope

- Rate limiting. `NET-003`.
- Rejection telemetry. `TEL-003`.
- Any real remote of the game. Still a test-only declaration.
- Per-player phase state. Phase is a property of the round, not of a player. A
  player who is mid-reconnect is handled by identity (`isSeated`) and by
  `SEAT-003`, not here.
- Grace for a call that was in flight when the phase changed. The server's phase at
  the moment of receipt is the phase; there is no reconciliation window, because a
  window is a thing an exploiter would aim for.

## Game design

Enforces the timing half of `mechanics.md` §5's validation list ("phase legality")
for every remote, ahead of the remotes that need it. The mechanic it will protect
is in §3: *"A group that attempts operation k+1 before k — rejected; instability
+1."* That rule is only meaningful if the server is the one deciding when k+1 is
legal.

No tuning constant is introduced or changed.
