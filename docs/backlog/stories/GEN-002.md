## Context

Epic: `EPIC-04`. This story places machines into a generated layout
(`mechanics.md` §1, §3.1, G2–G4, G12; `tuning.md` §2):

- `procedure_length` is 8 at every n from 4 to 6.
- Steps per class are balanced: 2,2,2,2 at n = 4, 2,2,2,1,1 at n = 5 and
  2,2,1,1,1,1 at n = 6. The seed chooses which classes get two.
- Every class has exactly one decoy per step, so the class sizes sum to
  `actuator_count` (`INV_class_machines`).
- Each room holds between `machines_per_room_min` and `machine_slots_per_room`
  machines, one per quadrant slot (`INV_room_capacity`).
- Tags come from one global alphabet of `tag_alphabet_size` shapes, drawn
  without replacement within each class (`INV_tags_distinct_in_class`).
- Every machine, decoys included, has a required setting drawn uniformly and
  independently from `1..dial_settings` (`INV_settings_uniform`). A decoy
  without one could be spotted by its missing glow.

The required settings are the game's central secret (`roles.md` §6). This story
only generates them. `VIEW-001` decides who may see them.

**Which required gate would fail if this story's artifact broke:** `unit`.

## Acceptance criteria

- **AC-1** — Given n in `{4, 5, 6}` and a sweep of at least 1,000 seeds per n,
  when `Machines.generate` runs, then the per-class step counts are the balanced
  split of `procedure_length` over n (each `floor(8/n)` or `ceil(8/n)`, summing
  to 8), and each class has exactly `actuator_redundancy` × its step count
  machines (`INV_class_machines`).
  *Control:* `Machines.check` must report `INV_class_machines` for a hand-built
  placement that gives one class 5 machines.
- **AC-2** — Given the same sweep, when rooms are counted, then every room holds
  between `machines_per_room_min` and `machines_per_room_max` machines, each in a
  distinct slot `1..machine_slots_per_room` (`INV_room_capacity`).
  *Control:* `check` must report an empty room and two machines in one slot.
- **AC-3** — Given the same sweep, when tags are read per class, then they are
  pairwise distinct within the class and each is in `1..tag_alphabet_size`
  (`INV_tags_distinct_in_class`).
  *Control:* `check` must report a class with two machines tagged 3.
- **AC-4** — Given the sweep, when required settings are pooled over all
  machines, then every machine has one in `1..dial_settings`, and each value's
  frequency lies within `1/dial_settings` ± 0.02. Decoys and future steps are
  pooled separately and each pool passes on its own.
  *Controls:* a generator that gives decoys no setting must fail the first
  clause. One that draws settings from `1..dial_settings − 1` must fail the
  frequency check, with setting 4 at about 0.
- **AC-5** — Given a machine's room and slot, when `Machines.positionOf` is
  called, then it returns the room centre plus the slot's quadrant offset of
  ± `room_pitch_studs` / 4 on each axis. Any two machines are at least
  `machine_spacing_min_studs` apart.
- **AC-6** — Given n in `{5, 6}` and the sweep, when which classes receive the
  extra step is tallied, then every class receives it in some seeds. The
  choice is drawn, not always the lowest classes.
  *Control:* a generator that always gives the extra steps to classes 1..k must
  fail.

## Contract

**Module.** `src/server/facility/Machines.luau`, pure.

    export type Machine = {
        id: number,              -- 1..actuator_count, in (room id, slot) order
        room: number,            -- Layout room id
        slot: number,            -- 1..machine_slots_per_room: 1 (−x,−z), 2 (+x,−z), 3 (−x,+z), 4 (+x,+z)
        keyClass: number,        -- Ring.KeyClass
        tag: number,             -- 1..tag_alphabet_size
        requiredSetting: number, -- 1..dial_settings   (SECRET: never replicated whole, roles.md §6)
    }
    export type Placement = { machines: { Machine }, stepsPerClass: { [number]: number } }

    Machines.generate(rng: Rng.Rng, layout: Layout.Layout, classes: { number }, tuning) -> Placement
    Machines.check(placement: Placement, layout: Layout.Layout, classes: { number }, tuning) -> { string }
    Machines.positionOf(layout: Layout.Layout, machine: Machine, tuning) -> { x: number, y: number, z: number }

- `classes` is the list of key classes in play at generation, which is
  `1..n` from the ring (`Ring.Assignment.keyClasses`). This module does not read
  σ.
- **World coordinates.** A room's centre is
  `((column − 1) × room_pitch_studs, 0, (row − 1) × room_pitch_studs)`. Machine
  positions have `y = 0`. **Every range rule in M3 measures horizontal (x, z)
  distance**, because the facility is one storey. Recorded in
  `architecture.md` §9.8.
- Sub-streams: `"counts"`, `"rooms"`, `"tags"`, `"settings"`, each derived from
  the `Rng` the caller passes (`GEN-004` passes the attempt's `"machines"`
  sub-stream).
- `stepsPerClass` is carried on the placement because `GEN-003` must choose
  exactly that many steps from each class.

**Oracle partition.** AC-1 to AC-3 and AC-5 are **settled** by `tuning.md` and
`mechanics.md`: read the constants, and never restate them. AC-4 and AC-6 are
**oracle-free** statistics with hand-written wrong generators as controls. The
tolerances are the Lead PO's starting point, and RED may tighten them from a
measured variance.
