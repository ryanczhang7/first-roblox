## Context

Epic: `EPIC-04`. This story places machines into a generated layout
(`mechanics.md` §1, §3.1, G2–G4, G12; `tuning.md` §2):

- `procedure_length` is 8 at every n from 4 to 6.
- Steps per class are balanced: 2,2,2,2 at n = 4, 2,2,2,1,1 at n = 5 and
  2,2,1,1,1,1 at n = 6. The seed chooses which classes get two.
- Every class has exactly one decoy per step, so the class sizes sum to
  `actuator_count` (`INV_class_machines`).
- Each room holds between `machines_per_room_min` and `machine_slots_per_room`
  machines, one per quadrant slot (`INV_room_capacity`).
- Tags come from one global alphabet of `tag_alphabet_size` shapes, drawn
  without replacement within each class (`INV_tags_distinct_in_class`).
- Every machine, decoys included, has a required setting drawn uniformly and
  independently from `1..dial_settings` (`INV_settings_uniform`). A decoy
  without one could be spotted by its missing glow.

The required settings are the game's central secret (`roles.md` §6). This story
only generates them. `VIEW-001` decides who may see them.

**Which required gate would fail if this story's artifact broke:** `unit`.

## Acceptance criteria

- **AC-1** — Given n in `{4, 5, 6}` and a sweep of at least 1,000 seeds per n,
  when `Machines.generate` runs, then the per-class step counts are the balanced
  split of `procedure_length` over n (each `floor(8/n)` or `ceil(8/n)`, summing
  to 8), and each class has exactly `actuator_redundancy` × its step count
  machines (`INV_class_machines`).
  *Control:* `Machines.check` must report `INV_class_machines` for a hand-built
  placement that gives one class 5 machines.
- **AC-2** — Given the same sweep, when rooms are counted, then every room holds
  between `machines_per_room_min` and `machines_per_room_max` machines, each in a
  distinct slot `1..machine_slots_per_room` (`INV_room_capacity`).
  *Control:* `check` must report an empty room and two machines in one slot.
- **AC-3** — Given the same sweep, when tags are read per class, then they are
  pairwise distinct within the class and each is in `1..tag_alphabet_size`
  (`INV_tags_distinct_in_class`).
  *Control:* `check` must report a class with two machines tagged 3.
- **AC-4** — Given the sweep, when required settings are pooled over all
  machines separately for each n, then every machine has one, an integer in
  `1..dial_settings`, and in each n's pool each value's frequency lies within
  `1/dial_settings` ± 0.02.
  *Controls:* a generator that leaves the last machine of each class (by id)
  without a setting must fail the first clause. One that draws settings from
  `1..dial_settings − 1` must fail the frequency check, with setting 4 at
  about 0. (Which machines are decoys is not known until `GEN-003`; the
  steps-versus-decoys pooling lives there as its AC-7. PO-1.)
- **AC-5** — Given a machine's room and slot, when `Machines.positionOf` is
  called, then it returns the room centre plus the slot's quadrant offset of
  ± `room_pitch_studs` / 4 on each axis. Any two machines are at least
  `machine_spacing_min_studs` apart.
- **AC-6** — Given n in `{5, 6}` and the sweep, when which classes receive the
  extra step is tallied, then every class receives it in some seeds. The
  choice is drawn, not always the lowest classes.
  *Control:* a generator that always gives the extra steps to classes 1..k must
  fail.

## Contract

**Module.** `src/server/facility/Machines.luau`, pure.

    export type Machine = {
        id: number,              -- 1..actuator_count, in (room id, slot) order
        room: number,            -- Layout room id
        slot: number,            -- 1..machine_slots_per_room: 1 (−x,−z), 2 (+x,−z), 3 (−x,+z), 4 (+x,+z)
        keyClass: number,        -- Ring.KeyClass
        tag: number,             -- 1..tag_alphabet_size
        requiredSetting: number, -- 1..dial_settings   (SECRET: never replicated whole, roles.md §6)
    }
    export type Placement = { machines: { Machine }, stepsPerClass: { [number]: number } }

    Machines.generate(rng: Rng.Rng, layout: Layout.Layout, classes: { number }, tuning) -> Placement
    Machines.check(placement: Placement, layout: Layout.Layout, classes: { number }, tuning) -> { string }
    Machines.positionOf(layout: Layout.Layout, machine: Machine, tuning) -> { x: number, y: number, z: number }

- `classes` is the list of key classes in play at generation, which is
  `1..n` from the ring (`Ring.Assignment.keyClasses`). This module does not read
  σ.
- **World coordinates.** A room's centre is
  `((column − 1) × room_pitch_studs, 0, (row − 1) × room_pitch_studs)`. Machine
  positions have `y = 0`. **Every range rule in M3 measures horizontal (x, z)
  distance**, because the facility is one storey. Recorded in
  `architecture.md` §9.8.
- Sub-streams: `"counts"`, `"rooms"`, `"tags"`, `"settings"`, each derived from
  the `Rng` the caller passes (`GEN-004` passes the attempt's `"machines"`
  sub-stream).
- `stepsPerClass` is carried on the placement because `GEN-003` must choose
  exactly that many steps from each class. Its key set is exactly `classes`;
  every value is `floor(procedure_length / n)` or `ceil(...)`, and they sum to
  `procedure_length`. Which classes get the ceiling is drawn from `"counts"`;
  no test pins which classes a given seed picks, only AC-6's coverage.
- **Machines in a placement** are listed with `machines[i].id == i`, ids in
  ascending `(room, slot)` order. Every class `c` has
  `actuator_redundancy × stepsPerClass[c]` machines. A machine's `room` is a
  `Layout` room id; `slot` is an integer in `1..machine_slots_per_room` with the
  quadrant mapping in the type above. How machines are spread over rooms is
  the implementer's choice, drawn from `"rooms"`, subject only to
  `INV_room_capacity`.
- **Tags.** Each class draws its tags from `1..tag_alphabet_size` without
  replacement (`"tags"`), independently of other classes.
- **Settings.** Each machine's `requiredSetting` is
  `nextInteger(1, dial_settings)` from `"settings"`, one draw per machine, read
  from nothing else (`INV_settings_uniform`).
- **`positionOf`** returns
  `centre(room) + (sx × room_pitch_studs / 4, 0, sz × room_pitch_studs / 4)`,
  where `(sx, sz)` is `(−1,−1)`, `(+1,−1)`, `(−1,+1)`, `(+1,+1)` for slots 1–4.
  At the current tuning the offsets are ±16 studs, but the test reads
  `room_pitch_studs` and never writes 16.
- **Purity.** No function mutates `layout`, `classes`, `tuning` or a
  `placement` it is given. `generate` derives exactly the four labels above and
  draws from nothing else, so the same rng, layout and classes give a
  deep-equal placement.
- **`check`** returns one string per violated clause. Each string **starts
  with** the invariant name, a colon, one token below, then a space and free
  text. A valid placement returns `{}`. Each control produces its own token.

  | prefix:token | clause |
  |---|---|
  | `INV_class_machines:steps` | `stepsPerClass` keys are not exactly `classes`, a count is outside floor/ceil, or they do not sum to `procedure_length` |
  | `INV_class_machines:count` | some class's machine count ≠ `actuator_redundancy` × its step count, a machine's `keyClass` is not in `classes`, or the total ≠ `actuator_count` |
  | `INV_room_capacity:count` | a room holds fewer than `machines_per_room_min` or more than `machines_per_room_max` machines |
  | `INV_room_capacity:slot` | a slot is outside `1..machine_slots_per_room`, two machines share a (room, slot), or a machine names an unknown room |
  | `INV_tags_distinct_in_class:tag` | two machines in one class share a tag, or a tag is outside `1..tag_alphabet_size` |
  | `INV_settings_uniform:setting` | a machine's `requiredSetting` is missing, not an integer, or outside `1..dial_settings` |

  Frequency (the "uniform" half of `INV_settings_uniform`) is a sweep property,
  asserted by AC-4's statistic, never by `check`.

### The export shape the tests pin

`require("../../src/server/facility/Machines")` must return a table with
three **plain field functions, called with a dot**:

    Machines.generate(rng: Rng.Rng, layout: Layout.Layout, classes: { number }, tuning: MechanicsTuning.MechanicsTuning) -> Placement
    Machines.check(placement: Placement, layout: Layout.Layout, classes: { number }, tuning) -> { string }
    Machines.positionOf(layout: Layout.Layout, machine: Machine, tuning) -> { x: number, y: number, z: number }

`tuning` is always the whole `MechanicsTuning` module table (read through
`tuning.instance.<name>`), as in `Layout`.

What the assertions destructure and therefore fix:

- **`Placement` value**: a table with **exactly** the keys `machines`,
  `stepsPerClass` and no others. `machines[i]` has exactly the keys `id`,
  `room`, `slot`, `keyClass`, `tag`, `requiredSetting`, all numbers.
  `stepsPerClass` has number keys and number values, key set exactly
  `classes`.
- **`generate`**: `machines[i].id == i`; strictly ascending `(room, slot)`;
  every class `c` in `classes` has `actuator_redundancy × stepsPerClass[c]`
  machines; `#machines == actuator_count`; every `keyClass` in `classes`;
  every room id of the layout holds `machines_per_room_min..machines_per_room_max`
  machines; slots integers in `1..machine_slots_per_room`, no `(room, slot)`
  twice, every `room` a layout room id; tags integers in `1..tag_alphabet_size`,
  distinct within a class; `requiredSetting` an integer in `1..dial_settings`
  on every machine. `stepsPerClass` values each `floor(L / n)` or `ceil`,
  summing to `procedure_length`; at n = 5 and 6 every class is a ceil class
  in some seed of 1..1000 (the test tallies `stepsPerClass[c] == ceil`). It
  must call `rng:derive("counts")`, `rng:derive("rooms")`, `rng:derive("tags")`,
  `rng:derive("settings")` **once each, in any order**, and must not call
  `nextInteger`, `nextNumber` or `shuffle` on the rng it was handed (a
  recording wrapper counts both). Deep-equal on the same seed, layout and
  classes. Pooled over 16,000 machines per n, each setting value's
  frequency within `1/dial_settings ± 0.02`.
- **The sweep's inputs**: layout `Layout.generate(Rng.fromSeed(s):derive("layout"), tuning)`,
  rng `Rng.fromSeed(s):derive("machines")`, classes `{1..n}` for n in 4, 5,
  6, seeds 1..1000. `generate` is also handed GEN-001's hand-built six-room
  "square" layout and must work from `layout.rooms`, not from `room_count`;
  `positionOf` is handed the five-room "plus" whose rooms are not the 2 × 3
  block, so room id must be looked up, not treated as a cell index.
- **`check`**: returns `{}` on every generated placement and on the three
  valid hand-built placements. On the 17 violation fixtures every returned
  string must start with one of the six heads **then a space**
  (`INV_class_machines:steps `, `INV_class_machines:count `,
  `INV_room_capacity:count `, `INV_room_capacity:slot `,
  `INV_tags_distinct_in_class:tag `, `INV_settings_uniform:setting `) - any
  other shape is counted malformed and fails - and the DISTINCT set of heads
  must equal the fixture's list exactly. The fixtures (all on the square
  layout, 16 machines in rooms 1..4 slots 1..3 and rooms 5..6 slots 1..2,
  classes dealt round-robin so sizes are 4,4,4,4 / 4,4,4,2,2 / 4,4,2,2,2,2,
  tag = ordinal within class) and their exact heads:
  - `stepsPerClass[5] = 0` at n = 4 -> `steps` alone (an extra key, nothing
    else wrong).
  - `stepsPerClass[4] += 1` at n = 4 -> `steps` **and** `count` (sum 9; class
    4 has 4 ≠ 6).
  - machine 9 (class 4) -> class 1, tag 1 at n = 5 (**AC-1's control**:
    class 1 has 5) -> `count` **and** `tag`. Five machines cannot carry five
    distinct tags from a four-shape alphabet, so `tag` must fire too.
  - machine 9 -> class 5, tag 3 at n = 5 -> `count` alone (classes 5 and 4
    have 3 and 1).
  - machine 16 `keyClass = 5` at n = 4 -> `count` alone.
  - machine 16 removed at n = 4 -> `count` alone (total 15; room 6 still
    holds one).
  - machines 15, 16 moved to room 5 slots 3, 4 -> room `count` alone (room 6
    empty; room 5 holds 4).
  - machine 2 `slot = 1` -> `slot` alone (shares room 1 slot 1 with machine 1;
    ordering is not a `check` clause).
  - machine 2 `slot = machine_slots_per_room + 1`; machine 2 `slot = 0`;
    machine 16 `room = #rooms + 1` -> `slot` alone, each.
  - machine 5 (class 1, tag 2) `tag = 3` (**AC-3's control**); machine 5
    `tag = tag_alphabet_size + 1` -> `tag` alone, each.
  - machine 7 `requiredSetting = nil`; `= dial_settings + 1`; `= 0`; `= 2.5`
    -> `setting` alone, each. So the range check must reject a missing value,
    a non-integer, and both ends.
  One string per violated clause is enough; reporting a clause more than once
  is tolerated (the test compares the distinct set), reporting an extra clause
  is not.
- **`positionOf`**: returns a table with **exactly** the keys `x`, `y`, `z`;
  `y == 0`; `x = (column − 1) × pitch + sx × pitch / 4`,
  `z = (row − 1) × pitch + sz × pitch / 4` with `(sx, sz)` = (−1,−1),
  (+1,−1), (−1,+1), (+1,+1) for slots 1..4, compared with `==` (exact at the
  shipped pitch; the test reads `room_pitch_studs` and never writes 16 or
  64). It is handed a machine table built by the test (`id = 1, keyClass =
  1, tag = 1, requiredSetting = 1`) - only `room` and `slot` may be read.
  Over every generated placement the minimum horizontal `(x, z)` distance
  between two machines must be ≥ `machine_spacing_min_studs`; with the
  formula above it is exactly `pitch / 2` (measured on the reference).
- **No mutation**: after `check` and `positionOf` on every machine, the
  layout, the classes list and the placement deep-equal snapshots taken
  before.

What the tests do **not** constrain, and so stays the implementer's:

- which classes any seed makes ceil classes, which rooms and slots any seed
  fills, which tags any class draws (forbidden by the Contract; no test
  looks). The reference stub's construction (one machine per room first,
  then shuffled free slots; classes dealt by a shuffle of the `"rooms"`
  stream; tags a shuffled prefix of the alphabet per class) is one
  allowed construction, not the required one;
- the free text after a head and its space;
- how many draws each sub-stream takes, and their order;
- exported Luau **types** - the tests are untyped at the boundary (`any`),
  so `export type Machine/Placement` are for the typecheck gate, not for
  these tests;
- whether `check` would report more than one clause on a placement that
  breaks several beyond the fixtures above - only the listed sets are
  required;
- behaviour on a `classes` list that is not `1..n`, or on a layout with
  fewer rooms than `machines_per_room_min` requires or fewer slots than
  `actuator_count` needs.
