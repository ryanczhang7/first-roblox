## Context

Epic: `EPIC-08`. Brief M3 asks for "one map (modular, hard-surface ... generated
blockout geometry)". Under the third pass, the map is generated per round from
the layout (`mechanics.md` §1, G1–G2). The geometry follows `tuning.md` §2's
"The layout" table:

- rooms `room_pitch_studs` apart on the grid, abutting, with no corridors;
- ceilings `room_ceiling_studs` high;
- doorways `doorway_width_studs` × `doorway_height_studs`, centred in the
  shared wall;
- machines at the quadrant slots.

This story turns a `Facility` into a list of part specifications (pure, and
tested) and builds them in the place (impure, and checked in Studio). The walls
are also what the line-of-sight port raycasts against (`architecture.md` §9.6),
so wrong geometry is wrong game rules, not only a wrong look.

Creator Store assets are **not** used (`architecture.md` §10, an operator
question). Materials and lighting are placeholders for M4.

**Which required gate would fail if this story's artifact broke:** `unit` for
the specification. The built place is `D-1`.

## Acceptance criteria

- **AC-1** — Given any facility from a sweep of at least 200 seeds, when
  `Blockout.parts` runs, then every room has a floor and a ceiling spanning its
  cell. Every grid edge between two occupied rooms is a wall with a gap
  exactly `doorway_width_studs` wide and `doorway_height_studs` high at its
  centre **if and only if** a door joins them. Every outer edge of an occupied
  cell is a solid wall.
  *Control:* a builder that leaves a gap on every shared edge must fail on a
  layout with a non-door adjacency.
- **AC-2** — Given the same facilities, when machine anchor specs are read, then
  each machine's anchor sits at `Machines.positionOf` (x, z), and carries the
  machine's id as its name.
- **AC-3** — Given the same facilities, when every pair of solid specs is
  tested, then no two overlap by more than a wall's thickness at a corner. No
  spec lies outside the occupied cells' footprint.
- **AC-4** — Given two machines in one room, when the straight segment between
  them is tested against the wall specs, then it crosses none. Given two
  machines in adjacent rooms **without** a door, then it crosses a wall. This is
  the geometric fact the line-of-sight port relies on.

## Contract

Pinned by the Lead PO at PLANNED → RED, 2026-10-07. **RED may amend any block
below in place, with a one-line reason beside it; GREEN builds what the amended
block says.** Symbols: `P` = `room_pitch_studs` (64), `H` = `room_ceiling_studs`
(16), `W` = `doorway_width_studs` (8), `D` = `doorway_height_studs` (10),
`T` = `Blockout.WALL_THICKNESS` (1). Every number is read from `tuning.instance`
(or `T`), never written as a literal in the module.

**C-1. Modules and exports.**

    src/server/facility/Blockout.luau      -- pure: no Roblox API, no module state, never mutates an argument
        export type Vec3 = { x: number, y: number, z: number }
        export type PartSpec = {
            name: string,
            kind: "floor" | "ceiling" | "wall" | "machine",
            cframe: Vec3,   -- the part's CENTRE; axis-aligned, no rotation
            size: Vec3,     -- full extents, all > 0
        }
        Blockout.WALL_THICKNESS: number    -- = 1; engineering, not tuning
        Blockout.ANCHOR_SIZE: Vec3         -- = { x = 4, y = 6, z = 4 }; engineering placeholder for HUD-002
        Blockout.parts(facility: Generator.Facility, tuning: MechanicsTuning.MechanicsTuning) -> { PartSpec }

    src/server/facility/Machines.luau      -- one NEW export; nothing existing changes
        Machines.roomCentre(layout: Layout.Layout, roomId: number, tuning) -> Machines.Position
            -- ((column − 1) × P, 0, (row − 1) × P); raises, naming the id, for a room not in the layout
        -- positionOf keeps its signature and is re-expressed as roomCentre + quadrant offset

    src/server/facility/BlockoutBuilder.luau  -- impure; Studio-verified (D-1); no unit test
        BlockoutBuilder.build(specs: { Blockout.PartSpec }, parent: Instance) -> Folder

`Blockout.parts` reads only `facility.layout` (rooms, doors) and
`facility.placement.machines`, and returns plain tables (deep-equal across two
calls on the same input). The order of the returned list is not constrained.

**C-2. Floors and ceilings (AC-1).** Exactly one `floor` and one `ceiling` per
room, each sized `(P, T, P)` and centred on the room's cell horizontally
(`Machines.roomCentre` x, z). The floor's **top face is y = 0** (centre y = −T/2);
the ceiling's **bottom face is y = H** (centre y = H + T/2). Names are free.

**C-3. Walls (AC-1, AC-3).** A wall lies **on a grid line**: its thin axis is
`T`, centred on the line; it spans **y ∈ [0, H]** exactly; along the line it
covers exactly the cell edge, `[edge midpoint − P/2, edge midpoint + P/2]`, with
no extension past the vertex. **One** set of wall specs per edge, never one per
room (two coincident walls are an AC-3 overlap). How an edge is cut into specs
is the implementer's choice; what it must cover is not:

- **outer edge** (an occupied cell next to an unoccupied cell or the grid
  boundary): the whole `P × H` rectangle is covered;
- **shared edge with a door**: covered everywhere except the doorway, the
  rectangle `|u| < W/2, 0 ≤ y < D`, where `u` is the distance along the line
  from the edge midpoint. The doorway is open from the floor to `D`; above it,
  `[D, H]`, is wall (a lintel);
- **shared edge without a door**: the whole `P × H` rectangle is covered.

Names are free, but every wall spec's name starts with `Wall`.

**C-4. Machine anchors (AC-2).** One spec per machine, `kind = "machine"`,
`name = tostring(machine.id)` (machine 7 is `"7"`), `size = ANCHOR_SIZE`,
centred at `Machines.positionOf` x and z with **y = ANCHOR_SIZE.y / 2** (standing
on the floor). Anchors are not solid: AC-3's overlap and AC-4's crossing tests
read only floor, ceiling and wall specs. Machine visuals are `HUD-002`'s.

**C-5. What AC-3's words mean.** Let `I` be the intersection of two specs'
axis-aligned boxes. They **overlap** when `I` has extent > 1e-6 on all three
axes; touching faces do not overlap. An overlap is **allowed** iff `I`'s x and z
extents are both ≤ `T` (+1e-6): the corner column where two perpendicular walls
meet (T/2 × T/2 under C-3). A spec **lies outside the footprint** when its box is
not contained (to 1e-6) in any single occupied cell's square grown by `T/2` on x
and z, which is exactly the slack a wall centred on an outer grid line needs.

**C-6. What AC-4's words mean.** The segment runs between the two machines'
`positionOf` points **at y = 3** (an avatar's chest, under `D`). It **crosses** a
wall spec when it meets the box's interior (slab test, strict, 1e-6). A
segment between two slots of one room meets no wall at all; between rooms
adjacent without a door, it meets at least one.

**C-7. The builder (D-1 only).** `build` destroys any existing child of
`parent` named `Facility`, then creates a `Folder` named `Facility` under
`parent` holding one `Part` per spec: `Name`, `Size` and `CFrame` (position only)
from the spec; `Anchored = true` on every part; `CanCollide = true` on floor,
ceiling and wall; `CanCollide = false` and `Transparency = 0.5` on machine
anchors. It touches no Roblox global at module load. **Calling it on round entry
is `SLICE-007`'s** (its Context already lists "the blockout built on entry to
`Round`"): see PO decision 1.

**C-8. Oracle partition.**
- **Settled** (a number read out of `tuning.md` §2 and C-2 to C-4): AC-1, AC-2.
  The expected sizes, faces and gap edges are computed in the test from

- **Mechanical** (exact geometric predicates, a helper written in the test, no

- **Sweep:** seeds 1..200 at n = 4 (and n = 5 and 6 if the run stays well
  inside the unit gate's budget), each facility from the real

**C-9. Callers of changed signatures.** No existing export changes signature.
`Machines.positionOf` is re-expressed, not changed. Its callers, from
