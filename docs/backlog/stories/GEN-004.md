## Context

Epic: `EPIC-04`. `mechanics.md` §6.3 defines **par**: the duration of a
canonical schedule in which a naive group starts together in `spawn_room`,
takes the steps one at a time, and uses no anticipation, no guessing and no
presets. The helper and the turner walk in parallel. Each step is charged a
flat `par_ping_seconds` and `par_turn_seconds`, and the finale is one unit.
`INV_traversal` requires `par × schedule_slack ≤ round_seconds`. It is what
keeps the floor low (`loop.md` §1a): no facility is ever offered that a group
doing nothing clever could not finish.

`mechanics.md` §6.2 (G11) defines **resampling**. Attempt *i* draws only from
`derive("instance"):derive("attempt-" .. i)`. The first attempt that passes every
invariant is the facility. After `generator_attempts_max` failures the round
resolves `no_contest / generation_failed`. The sweep of at least 1,000 seeds is
the real guarantee.

**Which required gate would fail if this story's artifact broke:** `unit`.

## Acceptance criteria

- **AC-1** — Given hand-built facilities whose par is worked by hand from the
  pseudocode in `mechanics.md` §6.3, when `Par.compute` runs, then it returns
  that par exactly. The fixtures are:
  1. everything in `spawn_room`;
  2. a chain layout, where the worst case is about 371 s by the
     `schedule_slack` rationale;
  3. a finale whose two pairs have different walks, where only the longer
     counts;
  4. a helper and a turner starting in different rooms.

  *Controls:* a `compute` that sums the helper's and the turner's walks
  instead of taking the maximum must fail fixture 4. One that adds the finale's
  two sub-steps sequentially must fail fixture 3.
- **AC-2** — Given a seed and a ring, when `Generator.generate` runs, then it
  returns the facility from the first attempt whose layout, placement and steps
  pass every invariant **and** whose par satisfies `INV_traversal`. The facility
  records that attempt's number. The same seed and ring always give the same
  facility.
- **AC-3** — Given a stage whose draws change (a test wrapper that consumes one
  extra number from the `"machines"` sub-stream), when `generate` runs for the
  same seed, then the layout of the accepted attempt is unchanged. Sub-streams
  isolate stages (D2).
- **AC-4** — Given an injected predicate that fails every attempt, when
  `generate` runs, then after exactly `generator_attempts_max` attempts it
  returns `{ kind = "failed" }` with one failure record per attempt, each naming
  the invariant that failed. It never returns a facility that failed an
  invariant.
- **AC-5** — Given n in `{4, 5, 6}` and at least 1,000 seeds per n, when
  `generate` runs, then every seed yields a facility within the bound, every
  facility satisfies every invariant including `INV_traversal`, and the
  first-attempt acceptance rate per n is printed. **If it is below 0.25 for any
  n, the test still passes, but the story stops at GATES and the Lead PO takes
  the number to the Game Designer.** `tuning.md: generator_attempts_max` says
  this is a design finding, not a reason to raise the bound.
- **AC-6** — Given a facility, when it is read, then it carries `layout`,
  `placement`, `steps`, `spawnRoom`, `par` and `attempt`, and nothing that is
  not a function of those and the seed.

## Contract

**Modules.** `src/server/facility/Par.luau` and
`src/server/facility/Generator.luau`, both pure.

    Par.compute(layout: Layout.Layout, placement: Machines.Placement, steps: Steps.Steps,
                assignment: Ring.Assignment, tuning) -> number

    export type Facility = {
        layout: Layout.Layout, placement: Machines.Placement, steps: Steps.Steps,
        spawnRoom: number, par: number, attempt: number,
    }
    export type GenerateResult = { kind: "facility", facility: Facility }
                               | { kind: "failed", failures: { { attempt: number, invariant: string } } }
    Generator.generate(assignment: Ring.Assignment, seed: number, tuning,
                       predicateOverride: ((Facility) -> string?)?) -> GenerateResult

- `helper(s)` is the holder of the lens for the key class of `s`'s machine.
  `turner(s)` is the holder of that key class. Both come from `Ring`, never a
  private σ.
- `predicateOverride` exists only for AC-4. When present, it runs **after** the
  real invariants, and a non-nil string fails the attempt. Production passes
  nil.
- Per attempt: `local a = Rng.fromSeed(seed):derive("instance"):derive("attempt-" .. i)`,
  then `a:derive("layout")`, `a:derive("machines")` and `a:derive("steps")`
  (`architecture.md` §9.3).
- `Session` maps a `failed` result to `RoundResolved{ no_contest,
  generation_failed }` in `SLICE-005`, not here.

**Runtime.** AC-5 runs at least 3,000 generations. Measure it under the gate
command, not the plain test command (`stack.md` §5, `--fast`). If it takes more
than 30 s, record the number, and the Lead PO decides whether to shrink the
per-n sample to the 1,000-seed total or to mark it `slow`. **Never drop the
sweep.**

**Oracle partition.**
- AC-1 is **settled**. The pseudocode is the oracle, and each fixture's
  expected par is written as the arithmetic, not as a bare number.
- AC-2 to AC-4 and AC-6 are **mechanical**.
- AC-5 is **settled** for the invariants and a **measurement** for the
  acceptance rate.

## Deferred verifications

**D-1. Par is the maximum, not the sum.** Use `scripts/mutate.sh` to change
the parallel walk to a sum. AC-1 fixture 4 **must** then fail, and the sweep
**must** show a higher rejection rate. RED cannot run this. Owner: GATES.

**D-2. `INV_traversal` is enforced by the generator, not just asserted by the
sweep.** Use `scripts/mutate.sh` to delete the generator's `INV_traversal`
check. AC-5 **must** then fail, because the sweep recomputes `par ×
schedule_slack` independently for every facility, and some seed produces a
layout long enough to violate it (the chain case in `tuning.md: schedule_slack`).
If no seed in the sweep does, the sweep cannot see this check. Record that, and
add a seed that does. Owner: GATES.

## Out of scope

- Recomputing par during a round. Par is computed once (`mechanics.md` §6.3),
  and there is no `unwinnable` check in M3 (§8).
- Showing par (`TRACE-002`).
