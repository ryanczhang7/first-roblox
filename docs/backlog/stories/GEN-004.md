## Context

Epic: `EPIC-04`. `mechanics.md` §6.3 defines **par**: the duration of a
canonical schedule in which a naive group starts together in `spawn_room`,
takes the steps one at a time, and uses no anticipation, no guessing and no
presets. The helper and the turner walk in parallel. Each step is charged a
flat `par_ping_seconds` and `par_turn_seconds`, and the finale is one unit.
`INV_traversal` requires `par × schedule_slack ≤ round_seconds`. It is what
keeps the floor low (`loop.md` §1a): no facility is ever offered that a group
doing nothing clever could not finish.

`mechanics.md` §6.2 (G11) defines **resampling**. Attempt *i* draws only from
`derive("instance"):derive("attempt-" .. i)`. The first attempt that passes every
invariant is the facility. After `generator_attempts_max` failures the round
resolves `no_contest / generation_failed`. The sweep of at least 1,000 seeds is
the real guarantee.

**Which required gate would fail if this story's artifact broke:** `unit`.

## Acceptance criteria

- **AC-1** — Given hand-built facilities whose par is worked by hand from the
  pseudocode in `mechanics.md` §6.3, when `Par.compute` runs, then it returns
  that par exactly. The fixtures are:
  1. everything in `spawn_room`;
  2. a chain layout, where the worst case is about 371 s by the
     `schedule_slack` rationale;
  3. a finale whose two pairs have different walks, where only the longer
     counts;
  4. a helper and a turner starting in different rooms.

  *Controls:* a `compute` that sums the helper's and the turner's walks
  instead of taking the maximum must fail fixture 4. One that adds the finale's
  two sub-steps sequentially must fail fixture 3.
- **AC-2** — Given a seed and a ring, when `Generator.generate` runs, then it
  returns the facility from the first attempt whose layout, placement and steps
  pass every invariant **and** whose par satisfies `INV_traversal`. The facility
  records that attempt's number. The same seed and ring always give the same
  facility.
- **AC-3** — Given a stage whose draws change (a test wrapper that consumes one
  extra number from the `"machines"` sub-stream), when `generate` runs for the
  same seed, then the layout of the accepted attempt is unchanged. Sub-streams
  isolate stages (D2).
- **AC-4** — Given an injected predicate that fails every attempt, when
  `generate` runs, then after exactly `generator_attempts_max` attempts it
  returns `{ kind = "failed" }` with one failure record per attempt, each naming
  the invariant that failed. It never returns a facility that failed an
  invariant.
- **AC-5** — Given n in `{4, 5, 6}` and at least 1,000 seeds per n, when
  `generate` runs, then every seed yields a facility within the bound, every
  facility satisfies every invariant including `INV_traversal`, and the
  first-attempt acceptance rate per n is printed. **If it is below 0.25 for any
  n, the test still passes, but the story stops at GATES and the Lead PO takes
  the number to the Game Designer.** `tuning.md: generator_attempts_max` says
  this is a design finding, not a reason to raise the bound.
- **AC-6** — Given a facility, when it is read, then it carries `layout`,
  `placement`, `steps`, `spawnRoom`, `par` and `attempt`, and nothing that is
  not a function of those and the seed.

`attempt` lives on the `Facility`, as AC-6 says. `architecture.md` §9.3 sketched
it at the top level of the result, and was aligned with this block at PLANNED
(PO-2).

**C-2. Par, exactly as `mechanics.md` §6.3 writes it.**
- `walk(a, b) = Layout.distance(layout, a, b) × tuning.instance.room_traversal_seconds`.
  `Layout.distance` is GEN-001's shortest doorway path in edges, 0 when a = b.
- The start position of every seated player is `layout.spawnRoom`, the field.
  It is not recomputed, so a hand-built fixture's `spawnRoom` is what par
  starts from.
- `room(s)` is the `room` of the placement machine whose `id` is `s`.
- `turner(s)` is the seated player whose `assignment.keyClasses` list contains
  the machine's `keyClass`. `helper(s)` is the player `p` with
  `Ring.lensOf(assignment, p) == keyClass`, which is `Ring.supplierOf(turner)`.
  Both are read through `Ring` and `assignment`. σ is never recomputed.
- Order: the ordinary steps are `tracks[t][1 .. steps_per_track - 1]`, taken
  T1[1], T2[1], T1[2], T2[2], and so on. If one track runs out first, the rest
  of the other follows in order. Each ordinary step adds
  `max(walk(pos[helper], room), walk(pos[turner], room)) + par_ping_seconds +
  par_turn_seconds`, then moves both to `room`. Nobody else moves.
- The finale is `steps.finale` (= the last step of each track). It is one unit:
  `max over both sub-steps of max(helper walk, turner walk)` +
  `par_ping_seconds` + `par_turn_seconds`, added once.
- The return value is seconds. It is an exact sum of tuning products, with no
  rounding.

**C-3. `INV_traversal`.** `par × tuning.instance.schedule_slack ≤ round_seconds`,
where `round_seconds` is `Tuning.round.round_seconds`, read from `@shared/Tuning`
at load. `MechanicsTuning` does not carry it, and a second copy would be a
second place for it to live. The comparison is `≤`, so equality is accepted. A
test that needs every attempt to fail `INV_traversal` passes a
`MechanicsTuning` fake with a large `schedule_slack`. It never edits
`round_seconds`.

**C-4. One attempt.** For `i = 1 .. generator_attempts_max`:

    local a = Rng.fromSeed(seed):derive("instance"):derive("attempt-" .. i)
    classes   = the sorted union of every list in assignment.keyClasses   -- {1..n} at generation
    layout    = stages.layout(a:derive("layout"), tuning)
    placement = stages.machines(a:derive("machines"), layout, classes, tuning)
    steps     = stages.steps(a:derive("steps"), layout, placement, assignment, tuning)
    par       = Par.compute(layout, placement, steps, assignment, tuning)

`stages.X` is `stagesOverride.X` when present, and otherwise the real module
function. Each sub-stream is derived from `a` once and handed to exactly one
stage. The invariants are evaluated **in this order**, and the first non-empty
report ends the attempt:
`Layout.check(layout, tuning)`, then
`Machines.check(placement, layout, classes, tuning)`, then
`Steps.check(steps, layout, placement, assignment, tuning)`, then
`INV_traversal`, then `predicateOverride(facility)` when one is passed. A stage
whose upstream check failed is **not** run. A malformed layout is not handed to
`Machines.generate`.

**C-5. Failure records.** One `{ attempt = i, invariant = s }` per failed
attempt, in attempt order. `s` is the **first string of the failing report,
verbatim**: GEN-001..GEN-003's `"<INV>:<token> free text"`, or for traversal
`"INV_traversal:par " .. free text` (the free text should carry par, slack and
`round_seconds`, but the tests pin only the head `INV_traversal:par `). For
the override, `s` is the override's return value, verbatim. If all
`generator_attempts_max` fail, the result is `{ kind = "failed", failures = …
}` with exactly that many records. `failures` exists only on a failed result,
and `facility` only on a facility result.

**C-6. The facility.** `{ layout, placement, steps, spawnRoom =
layout.spawnRoom, par, attempt = i }`, exactly these six keys (AC-6). `par` is
`Par.compute`'s value for these arguments. The facility is not frozen deeply,
and nothing is required either way. Tests compare it by value.

**C-7. AC-3's wrapper is `stagesOverride`.** It is the "test wrapper" AC-3
names, and it exists only for AC-3, as `predicateOverride` exists only for
AC-4. Production passes nil for both. The AC-3 test:
- wraps `machines` with `function(rng, ...) local extra = rng:nextNumber();
  return Machines.generate(rng:derive("__wrapped-" .. extra), ...) end`.
  **Amended in RED (2026-10-01, test-developer):** the block originally read
  `rng:nextNumber(); return Machines.generate(rng, ...)`, and the needle
  below fired on the *reference* generator - no placement differed on any of
  3,000 seeds. Under the shipped `Rng`, `derive(label)` builds the sub-stream
  from the parent's *identity* and never its *state*
  (`src/shared/Rng.luau`, `identityFor`), and `Machines.generate` derives all
  four of its streams and draws from the stream it is handed not at all, so
  an extra draw that is then discarded is invisible to the real stage. The
  number has to be *used*: it names the sub-stream the real stage runs on.
  This is still "one extra number from the `"machines"` sub-stream" (AC-3,
  unchanged), and the stage's draws now differ on every seed;
- asserts for every swept seed that the wrapped facility's `layout`
  deep-equals `Layout.generate(<attempt stream of the wrapped facility's own
  attempt>:derive("layout"), tuning)`. Where the wrapped and plain runs
  accepted the same attempt number, it also asserts their layouts are
  deep-equal. (The wrapped stage's draws differ, so the placement, and
  therefore par and which attempt is accepted, may change: in RED, the
  reference accepted the same attempt on 971 / 981 / 990 of 1000 seeds at
  n = 4 / 5 / 6. "The layout of the accepted attempt" is read this way.)
- **needle:** asserts that at least one seed's wrapped `placement` differs from
  the plain one. Otherwise the wrapper changed nothing and the test is vacuous.
- also asserts the `steps` stage is handed the same stream. A spy `steps`
  stage records `rng:derive("__spy"):nextNumber()` and then delegates to
  `Steps.draw`. `derive` reads only the stream's identity and consumes nothing,
  so the spy does not disturb the draw, and the recorded number must be equal
  with and without the machines wrapper for the same attempt.

**C-8. Sweep inputs (AC-5, and any test sampling seeds).** The same as GEN-003,
one level up. For seed `s` and n, the ring is
`Ring.assign({"p1", …, "pn"}, Rng.fromSeed(s))`, and the facility is
`Generator.generate(ring, s, MechanicsTuning)`. Seeds `1..1000` at each n in
`{4, 5, 6}`. The sweep **recomputes par with the test's own implementation of
§6.3**: its own BFS over `layout.doors` and its own helper/turner lookup from
`assignment.lens` and `assignment.keyClasses`. It checks `par ×
schedule_slack ≤ round_seconds` against that number and checks
`facility.par` equals it. It re-runs `Layout.check`, `Machines.check` and
`Steps.check` on the returned facility. A sweep that trusted `facility.par` or
`Par.compute` could not see D-1 or D-2. AC-5 prints, per n, the exact line
`[measured] Generator acceptance: n = <n>: <k> of 1000 first attempts accepted, rate <r>; max attempt <m>`.

### The export shape the tests pin

`require("../../src/server/facility/Par")` must return a **frozen** table
(`table.isfrozen`) with one plain field function, called with a dot:

    Par.compute(layout: Layout.Layout, placement: Machines.Placement, steps: Steps.Steps,
                assignment: Ring.Assignment, tuning: MechanicsTuning.MechanicsTuning) -> number

`require("../../src/server/facility/Generator")` must return a **frozen**
table with one plain field function:

    Generator.generate(assignment: Ring.Assignment, seed: number,
                       tuning: MechanicsTuning.MechanicsTuning,
                       predicateOverride: ((Facility) -> string?)?,
                       stagesOverride: { layout: fn?, machines: fn?, steps: fn? }?) -> GenerateResult

`tuning` is always the whole `MechanicsTuning`-shaped table, read through
`tuning.instance.<name>`; the tests also pass a **fake** built by
`Deep.copy(MechanicsTuning)` with `instance.schedule_slack = 1e9`, frozen at
every level - so read `generator_attempts_max`, `schedule_slack` and the par
constants from the *argument*, never from the module. `round_seconds` is NOT
on the argument: read `Tuning.round.round_seconds` from `@shared/Tuning`
(C-3); the test's oracle reads the same field.

What the assertions destructure and therefore fix:

- **`GenerateResult`**: a table whose keys are **exactly** `{ kind, facility }`
  with `kind == "facility"`, or **exactly** `{ kind, failures }` with
  `kind == "failed"`. Any other key, both, or neither fails `resultShapeProblem`.
- **`Facility`**: a table with **exactly** the keys `attempt`, `layout`,
  `par`, `placement`, `spawnRoom`, `steps` (compared sorted, so a seventh key
  - `seed`, `classes`, anything - fails AC-6). `spawnRoom == layout.spawnRoom`.
  `attempt` is an integer in `1..generator_attempts_max`. The whole facility
  is compared with `Deep.equal` against
  `{ layout = Layout.generate(a:derive("layout"), tuning), placement =
  Machines.generate(a:derive("machines"), layout, classes, tuning), steps =
  Steps.draw(a:derive("steps"), layout, placement, assignment, tuning),
  spawnRoom = layout.spawnRoom, par = <own §6.3>, attempt = i }` where
  `a = Rng.fromSeed(seed):derive("instance"):derive("attempt-" .. i)` and
  `classes` is the **sorted union** of every list in `assignment.keyClasses`
  (= `{1..n}` for every ring the tests build). Deep-equal means the layout,
  placement and steps must be exactly what those calls return - no extra
  fields, no reordering, no copy that drops a key. Freezing them deeply is
  allowed (`Deep.equal` does not care) and not required.
- **`par`** must equal the test's own §6.3 to the last bit (`==`, no
  tolerance): an exact sum of `distance × room_traversal_seconds` and the two
  constants. Four fixtures pin it by hand (values with the shipped constants:
  91, 283, 107, 187); 3,000 real first attempts pin it against the oracle.
  Order: `T1[1], T2[1], T1[2], T2[2], ...` over `tracks[t][1 .. last-1]`;
  each ordinary step `max(walk helper, walk turner) + ping + turn`, both
  move; the finale `max over the two sub-steps of max(helper, turner) +
  ping + turn`, once, with everyone where the ordinary steps left them.
  The turner of a class is the player whose `keyClasses` list contains it;
  the helper is the player whose `lens` **is** it. Walks start from
  `layout.spawnRoom`, the field.
- **`failures`**: a list of exactly `generator_attempts_max` tables with
  keys **exactly** `{ attempt, invariant }`, `attempt = 1..max` in order.
  `invariant` is: the override's return value **verbatim** when the override
  refused; otherwise the **first string** of the first non-empty report in
  the order `Layout.check`, `Machines.check`, `Steps.check` (compared
  verbatim, so `report[1]` as returned); otherwise a traversal string whose
  first 18 characters are **`INV_traversal:par `** (trailing space; the rest
  is free). The override is called **only** after the three checks and
  traversal pass, and is handed the facility that would otherwise be
  returned, with `attempt = i`; the test deep-copies what it receives and
  compares it to the recomposition.
- **`INV_traversal`** is `par * tuning.instance.schedule_slack <= Tuning.round.round_seconds`
  with `<=`. The huge-slack fake must fail *every* attempt this way.
- **`stagesOverride`**: when present, `stagesOverride.layout` /
  `.machines` / `.steps` replace the real stage functions and are called
  with **exactly** the real signatures: `layout(rng, tuning)`,
  `machines(rng, layout, classes, tuning)`, `steps(rng, layout, placement,
  assignment, tuning)`. Each is handed `a:derive("layout")` /
  `a:derive("machines")` / `a:derive("steps")`, derived from `a` once each.
  The spy asserts `rng:derive("__spy"):nextNumber()` on the stream handed to
  the steps stage equals `attemptRng(seed, i):derive("steps"):derive("__spy"):nextNumber()`
  for every attempt `i` up to the accepted one, so the steps stage must be
  handed that exact stream, and must be called once per attempt that reaches
  it (an attempt whose layout or machines check failed is **not** handed to
  the next stage). Passing `nil` overrides, a `{}` override, or a nil-returning
  predicate must give a result deep-equal to passing nothing.
- **Determinism**: deep-equal results for the same seed on the same ring and
  on a second ring of equal content; the test never relies on table identity.
- **Purity**: the assignment and the tuning deep-equal snapshots taken before
  `generate`; `Par.compute`'s five arguments likewise.

What the tests do **not** constrain, and so stays the implementer's:

- how `Par` walks the graph (`Layout.distance` as C-2 says, or its own BFS),
  whether it reads `steps_per_track` or `#track` for the ordinary steps (they
  agree on every valid Steps), and what it does on a malformed Steps - the
  generator never hands it one, and no test does;
- the free text after `INV_traversal:par ` (C-5 suggests par, slack and
  `round_seconds`);
- whether the facility, its sub-tables or the result are frozen;
- exported Luau **types** - the tests are untyped at the boundary (`any`),
  so `export type Facility` etc. are for the typecheck gate;
- behaviour on fewer than 4 players, on an assignment where a player holds
  two classes, or on a tuning whose `generator_attempts_max` is 0;
- whether the override is called with the same table that is returned or a
  copy (the test copies on receipt and compares by value);
- the order of keys and of stage *derivation* calls (only that each
  sub-stream is derived from `a`, and that `a` itself is never drawn from
  directly - nothing asserts the latter, but a direct draw from `a` cannot
  change anything a stage sees, because `derive` reads identity).
