## Context

Epic: `EPIC-08`. This story builds presets as the player sees them, using these
components from `docs/wiki/design/components.md`:

- **C-09, the Presets button.** It has a cooldown ring, a press during cooldown
  does not restart it, and a failed filter shows "not sent".
- **C-10, the preset panel.** A 2×5 grid of icon plus word. A tile illegal in
  the current phase stays in place, disabled. There is a cooling state. Keys
  1–0 select a tile while the panel is open, and LB opens it on gamepad.
- **C-11, the bubble** over the sender.
- **C-12, the beacon.** It stays where the preset was sent (Q-G7) and shows
  through walls. Its edge chevrons appear only for your helper or partner.
- **C-13, the chat line.** `system preset  {name}  {word}`, with no terminal
  punctuation (C6).

Compliance presentation is required (`mechanics.md` §4.2, §4.3 C6): icon plus
word, visually distinct from native chat, and labelled "system preset" inside
any chat surface. **The chat route depends on `CHAN-001`.** If CA-6's route is
not confirmed, C-13 is not built and AC-4 is waived with that reason.

**Which required gate would fail if this story's artifact broke:** `unit`. The
look is `D-1`.

## Acceptance criteria

- **AC-1** — Given `PresetPanelModel.entries(Presets.ALL, phase, cooldownUntil,
  now)`, when it runs in each phase, then it returns one entry per preset, in
  table order, each with its icon key and word. An entry is disabled with
  reason `phase` iff its phases exclude the current one, and with reason
  `cooling` while cooling. A disabled entry reports `selectable = false`
  (PT-A8).
- **AC-2** — Given `PresetBubbleModel` and `PresetBeaconModel`, when a
  `PresetShown` is described for a viewer, then the bubble shows the word, the
  icon and the sender's hue swatch, with the name in white (PT-T3's
  usage clause). The beacon's position is the payload's position, and its
  `edge` is true only when the sender is the viewer's helper or partner.
  *Control:* a beacon with edge chevrons for every sender must fail.
- **AC-3** — Given a preset, when the display timer is read, then the bubble and
  the beacon are gone after `preset_display_seconds`.
- **AC-4** (PT-C6) — Given `PresetChatModel.line(name, word)`, when it runs for
  every preset, then the line contains `system preset`, the word unmodified, and
  no line ends in `.`, `!` or `?`. A name containing `<b>` is escaped.
  **Waived with the reason recorded if `CHAN-001` does not confirm the route.**
- **AC-5** — Given `ActionButtonModel.describe` for the preset button, when a
  `PresetFailed` arrives, then the state is `not sent` and it is ready again
  after the attempt floor. After a shown preset, it cools for
  `preset_rate_limit_seconds`.

## Contract

The models are pure, in `src/client/models/`, per `components.md`:
`PresetPanelModel`, `PresetBubbleModel`, `PresetBeaconModel`,
`PresetChatModel`, and `ActionButtonModel` (shared with `HUD-003`). Presets are
sent with `ClientTransport.send("SendPreset", { preset = id })`. **Amend
`PresetChatModel` and the chat view from `CHAN-001`'s result before RED.**

**Oracle partition.**
- AC-1 to AC-5 are **settled** by `mechanics.md` §4.2 and §4.3, `tuning.md` §3
  and `components.md`.
