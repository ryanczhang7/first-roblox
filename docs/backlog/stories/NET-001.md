## Context

Brief **B4** calls the trust boundary "the highest-risk area for agent-generated
code" and gives the reason: generated Luau is prone to trusting remote arguments.
A3 pillar 4 is sharper — this is a social game and the entire product dies the day
it is exploitable.

B4's own rule is structural rather than procedural: *"Every remote gets a
server-side validation wrapper in `src/net/`. No raw `OnServerEvent:Connect` in
`src/server/`."* That is enforceable by a test, and this story writes it. Once it
exists, "did we remember to validate this one" stops being a per-story question.

Roblox clients are fully hostile: an exploiter can call any RemoteEvent with any
arguments, read any value replicated to them, and modify any LocalScript. There is
no such thing as a malformed call this server will not receive.

This story covers the first three checks of the pipeline — identity, shape, range.
`NET-002` adds phase legality, `NET-003` rate limiting, `TEL-003` the rejection
telemetry.

**Which required gate would fail if this story's artifact broke:** `unit`. The
adversarial tests and the no-`OnServerEvent` guard both run there.

## Acceptance criteria

- **AC-1** — Given a remote declared with a schema, when it is called by a seated
  player with arguments matching the schema, then the handler runs exactly once and
  receives the validated arguments.
- **AC-2** — Given that remote, when it is called with the wrong number of
  arguments, a wrong type, a missing required field, or an extra unexpected field,
  then the handler does **not** run and the rejection reason is
  `"shape"` in each case.
- **AC-3** — Given a remote whose schema declares a numeric range, when it is
  called with a number outside that range — below the minimum, above the maximum,
  `NaN`, `math.huge`, and a non-integer where an integer is declared — then the
  handler does not run and the reason is `"range"`, distinct from `"shape"`.
- **AC-4** — Given a remote, when it is called by a player who is not seated in the
  current round, then the handler does not run and the reason is `"identity"`.
- **AC-5** — Given a wrapper, when a **valid** call is made, then it is accepted.
  *Control:* a wrapper that rejects everything passes AC-2, AC-3 and AC-4 and
  **must** fail this. This criterion exists because "malformed calls are rejected"
  is satisfied by a boundary that rejects valid calls too, and that wrapper would
  ship.
- **AC-6** — Given each rejection, when the result is inspected, then it names
  **which check fired** — `identity`, `shape` or `range` — and the checks run in
  that order, so an unseated player sending a malformed payload is rejected for
  `identity`.
  *Control:* an implementation returning a single boolean `false` **must** fail
  this.
- **AC-7** — Given the source modules reported by
  `bash scripts/classify.sh --list source src`, when each is scanned, then
  `OnServerEvent`, `OnServerInvoke` and `.OnClientEvent` appear in no module
  outside `src/net/`.
  *Control:* a `__probe_` module under `src/server/` containing
  `remote.OnServerEvent:Connect(...)` **must** make this fail and **must** be named
  in the failure. Assert the scanned-set size too: a guard over zero files passes.
- **AC-8** — Given a remote declared twice with the same name, when the second
  declaration is made, then it fails rather than silently replacing the first.
  *Semantics:* a silently replaced declaration is a validated remote quietly
  becoming an unvalidated one.

## Contract

### `src/net/Schema.luau`

    export type Schema = { validate: (value: any) -> (boolean, string?) }

    Schema.integer(min: number, max: number) -> Schema   -- inclusive both ends
    Schema.number(min: number, max: number) -> Schema    -- inclusive; rejects NaN and inf
    Schema.boolean() -> Schema
    Schema.literal(...: string) -> Schema                -- one of the given strings
    Schema.shape(fields: { [string]: Schema }) -> Schema -- EXACT keys: no extras
    Schema.optional(inner: Schema) -> Schema

**`Schema.shape` is exact, not permissive.** An unexpected key is a rejection, not
an ignored field. A permissive shape validator is how an exploiter smuggles a field
that a later refactor starts reading.

**The failure string distinguishes `shape` from `range`.** A type error and a
domain violation are different attacks and a test must be able to tell which check
fired (AC-6). `NaN` and infinity are `range` failures, not `shape` ones — they are
numbers.

**Amended in RED (Test Developer, 2026-09-21) — the failure string LEADS with
the kind.** `validate` returns `(true, nil)` on acceptance and otherwise
`(false, "shape: <detail>")` or `(false, "range: <detail>")`: the kind, a colon,
a space, free text. *Reason:* the `Schema` type above is structural, so a
hand-written `{ validate = ... }` is a legal `args` and `Wrapper.guard` has to
read the kind out of the string — "distinguishes" left the *how* open, and a
substring search either way ("contains `shape`") is a needle whose negation is
also a match. The tests read it with `string.match(failure, "^(%l+):")`, and
`wrapper_test` pins the wrapper's side of the protocol with a spy schema:
`"range: X"` becomes `{ reason = "range", detail = <contains X> }`.

**Amended in RED (Test Developer, 2026-09-21) — a structural failure anywhere
in a payload beats a domain failure anywhere in it.** Against
`shape({ token = integer(1, 16), flag = boolean() })`, the payload
`{ token = 99, flag = "no" }` fails as `shape`, whatever order the fields are
iterated. *Reason:* the check order below makes shape and range pipeline
*stages*, and `validate` is the single entry point, so the order has to hold
inside one payload or AC-6's reason depends on hash-iteration order — which
makes `TEL-003`'s per-reason metric noise. A single-pass validator gets this
wrong by construction. GREEN meets it by whatever means; two passes over the
value — every structural check, then every domain check — is the obvious one.

### `src/net/Remotes.luau`

    export type RemoteDefinition = {
        name:        string,
        args:        Schema,
        legalPhases: { Phase },                  -- honoured by NET-002
        rateLimit:   { minIntervalSeconds: number }?,   -- honoured by NET-003
    }

    Remotes.define(name: string, spec) -> RemoteDefinition   -- errors on a duplicate name
    Remotes.all() -> { RemoteDefinition }

`legalPhases` and `rateLimit` are **declared now and enforced by the next two
stories**. Declaring them here means those stories change one file each and no
call site.

**Amended in RED (Test Developer, 2026-09-21) — `Remotes.all()` returns a
copy.** Inserting into the list it returns does not change what a later
`all()` returns. *Reason:* AC-8's semantics, read from the other side — a live
registry handed out is the quiet way a validated remote becomes an unvalidated
one. `remotes_test` pins it. The definition `define` returns carries `name`,
`args` (the same table that was passed, by identity), `legalPhases` and
`rateLimit` (nil when omitted); nothing else about its representation is
constrained.

### `src/net/Wrapper.luau`

    export type Rejection = {
        reason: "identity" | "shape" | "range" | "phase" | "rate",
        detail: string,
    }

    Wrapper.guard(
        definition: RemoteDefinition,
        context: GuardContext,
        handler: (playerId: PlayerId, args: any) -> ()
    ) -> (playerId: PlayerId, rawArgs: any) -> Rejection?

    export type GuardContext = {
        isSeated: (playerId: PlayerId) -> boolean,
        phase:    () -> Phase,        -- consumed by NET-002
        clock:    Clock,              -- consumed by NET-003
    }

The guarded function returns `nil` on acceptance and a `Rejection` otherwise. It
**never raises**: an exploiter must not be able to error a server thread by sending
a table where a number belongs.

`GuardContext` is injected, so the whole pipeline is tested with no Roblox, no
`Players` service and no round. That is the reason it is a parameter rather than a
`require`.

### Check order — fixed

    1. identity   -- is the sender a seated player in this round?
    2. shape      -- arity and types
    3. range      -- numeric domains
    4. phase      -- NET-002
    5. rate       -- NET-003

First failure wins and short-circuits. AC-6 pins it. Reordering later needs an
`## Amendments` entry: `TEL-003` emits the reason, and a reason that moves makes
every historical exploit metric incomparable.

### The types this layer may not import — checked, not remembered

`src/net/` **cannot** require `src/server/`. Two independent mechanisms say so,
and both were read out of the tree on 2026-09-21 rather than recalled:

- `architecture.md` §1: `server` imports from `shared` and `net`. The arrow does
  not run the other way.
- `.luaurc` declares exactly one alias — `"shared": "src/shared"` — and
  `architecture.md` §1 records why a relative require cannot cross a layer:
  `luau-lsp` resolves a string require through the Rojo sourcemap, where
  `src/net` is `game/ReplicatedStorage/Net` and `src/server/round` is
  `game/ServerScriptService/Server/round`. There is no spelling that resolves.

So:

| Type | Where it is today | What `src/net/` does |
|---|---|---|
| `Phase` | `src/server/round/PhaseMachine.luau:122` | **re-declares** it, identically |
| `PlayerId` | `PhaseMachine.luau:124`, `Ring.luau:60` (already twice) | **re-declares** `= string` |
| `Clock` | `src/shared/Clock.luau:20` | `require("@shared/Clock")` — the alias exists and this is the permitted direction |

Luau string-literal unions are structural, so a `Phase` produced by the phase
machine is accepted where `Remotes.Phase` is wanted and the reverse holds too.
Nothing at the boundary breaks.

**The drift this buys, named here rather than discovered later.** Two copies of
the phase union can disagree. Nothing in NET-001 *reads* `legalPhases`, so
nothing in this story can break on it — `NET-002` is the story that enforces
phase legality and the first that needs the two copies to agree. Giving the union
one home in `src/shared/` is `NET-002`'s call, with the caller list this story
did not need. See PO decision 3 in `## Notes`.

### `rawArgs` is one payload, so AC-2's "wrong number of arguments" is a key count

`Wrapper.guard` returns `(playerId: PlayerId, rawArgs: any)` — a single payload,
not a vararg list. AC-2 names four cases; this is what each one is, fixed here so
RED and GREEN read the criterion the same way. **This is a reading of AC-2, not a
change to it**: the criterion still asserts exactly what it asserted, and there
is no `## Amendments` entry because nothing was amended.

| AC-2's phrase | The call | Reason |
|---|---|---|
| wrong number of arguments | under one payload, arity **is** key count: `{}` and `{ token = 4, extra = 1 }` against a one-field shape | `shape` |
| a wrong type | `{ token = "4" }` where `Schema.integer` is declared | `shape` |
| a missing required field | `{ b = 1 }` against `shape({ a = ..., b = ... })` | `shape` |
| an extra unexpected field | `{ a = 1, b = 2, admin = true }` | `shape` |

Two more cases the signature admits and AC-2's prose does not name. Both are
`shape`, and RED writes them:

- `rawArgs` is `nil`;
- `rawArgs` is a non-table — a number, a string, a function — where a shape is
  declared. This is the one an exploiter actually sends, and the Contract already
  says the guarded function must not raise on it.

### `Schema.integer` rejects a non-integer for `range`, not `shape`

AC-3 lists "a non-integer where an integer is declared" among its `range` cases,
and the instinct is to call `3.5` a type error. It is not: `3.5` **is** a number,
and `Schema.integer(1, 10)` declares a *domain* — the integers in `[1, 10]` — of
which `3.5` is not a member, exactly as `11` is not. Same argument for `NaN` and
`math.huge`, which the Contract's Schema block already assigns to `range`;
`Schema.number(min, max)` rejects both for `range` too.

`shape` is reserved for **"this is not a number at all"**. Pinned because a
plausible implementation gets it backwards and AC-6 is the only thing that would
notice.

### AC-7's guard needs a MEMBER matcher, and the obvious reuse is vacuous

**The file list is `tests/helpers/SourceScan.luau` and nothing else.** It already
does this: `sourceFiles()`, `sourceFilesIn(pathspec)`, `classifierList(category,
pathspec)`, `nonSourceFilesUnderSrc()` for the control, `contains()`, and
`refresh()` — which a test that changes the tree must call after writing *and*
after removing. `rules.md` is emphatic about why a private glob is not an option.

**The matcher is a different question, and `SourceScan.hitsIn` is the wrong one.**
It was built for ROUND-001's globals — `os.clock`, `tick`, `math.random` — where
a field access is deliberately *not* a hit: `hitsIn` rejects any match whose
preceding non-space character is `.` or `:`, so that `self.tick` and
`{ tick = 2 }` do not fire. Every one of AC-7's three needles is a member access,
so every one is rejected.

Measured by the Lead PO on 2026-09-21 against `tests/helpers/SourceScan.luau` as
committed, over a four-line sample containing `remote.OnServerEvent:Connect(...)`,
`remote.OnServerInvoke = function(player) ... end` and `local c =
other.OnClientEvent`:

```
symbol OnServerEvent    -> 0 hit(s)
symbol OnServerInvoke   -> 0 hit(s)
symbol .OnClientEvent   -> 0 hit(s)
symbol OnClientEvent    -> 0 hit(s)
```

A guard reusing `hitsIn` therefore reports **green over a tree in which every
module connects a raw remote**. That is precisely the needle-that-cannot-fail
failure in `rules.md`: a sharp name, a real run, a pass, and nothing asserted.
AC-7's control is what catches it, which is why the control is not optional and
why AC-7 also demands the scanned-set size.

What RED writes is a **member** matcher in `SourceScan.luau` — a sibling of
`hitsIn`, never a change to it: ROUND-001's `source_guard_test.luau` and
ROUND-003's `roblox_runtime_guard_test.luau` both depend on the current
behaviour and are frozen tests. Reuse `codeOnly` so comments and string literals
are still blanked; `architecture.md` contains the sentence
"No `OnServerEvent:Connect` outside `src/net/`" and `src/shared/Scaffold.luau` is
this repository's precedent for why a guard that cannot tell a call from a
sentence about calls gets deleted.

### Why the code is shaped the way it is

- **Two passes, as the amended Contract requires, and they are load-bearing.**
  Each node exposes `checkShape` and `checkRange`; `validate` is the only place
  the `shape: ` / `range: ` prefix is written, so no constructor can forget it
  or invent a third kind, and a `shape()` node recurses into its fields *within*
  each pass. That is what makes a structural failure anywhere beat a domain
  failure anywhere, at any nesting depth. The `rangeBeforeShape` row above is
  the measurement that it is not decoration.
- **A missing required key needs no case of its own.** `payload[key]` is nil for
  an absent key, and nil fails every field schema structurally except
  `optional`, which is the node that declares nil legal. One rule, both AC-2's
  "missing required field" and `optional`'s semantics.
- **The extra-key scan tests `typeof(key)` before looking the key up**, so an
  array key and a table-valued key are rejections rather than raises -
  `{ token = 4, flag = true, [{}] = 1 }` is in the never-raises list.
- **`describe` truncates a string over 32 characters.** A 100 KB payload must
  not become a 100 KB rejection detail; the length is an attacker's choice.
- **`validate` runs under `pcall` in the wrapper, the handler does not.** The
  Contract's "never raises" is about exploiter input, and `args` may be any
  hand-written table with a `validate`; containing a *handler* error is a driver
  concern this story does not claim, and swallowing one would hide a defect.
- **The kind match is anchored** (`^(%l+):`), never a substring search: a needle
  whose negation also matches is the failure mode `rules.md` names, and
  `"not a range problem"` contains `range`.
- **`Phase` is re-declared in `Remotes.luau` and `Wrapper.luau` reuses it**
  (`Remotes.Phase`) rather than making a third copy. `PlayerId` is declared in
  `Wrapper.luau`, the only module that has one. `Clock` is
  `require("@shared/Clock")`.
